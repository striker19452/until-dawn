手机竖屏末日经营游戏。当前开发版已贯通第1天到第28夜后的救援：白天用指令搜索、建设和分工，夜间在同一院子中连续呈现入侵、修补、驱赶和添火。可以独居，也可以招募至五人，包含主角。

前端采用 HTML5、CSS、JavaScript、Phaser 4 和 Vite；存档使用浏览器 IndexedDB，夜战完全由浏览器 Web Worker 计算；Node.js 提供静态页面及旧版 SQLite 存档迁入接口。界面固定在一个屏幕中：院子、资源、防区与常用指令同屏，建设、成员、外出与故事用底部抽屉切换。院子采用昼夜两张精绘背景，人物、生物、设施和道具使用透明手绘图集；[素材与完整提示词](ASSET_PROMPTS.md)已保留。已保留旧版首日代码和存档，新版首次打开时将已有 campaign 进度与清晨检查点一起迁入本机浏览器。

场景画布按显示尺寸与设备像素密度生成，支持手机Retina高清绘制，480单位的游戏坐标与物理像素分离。界面保持单屏大小，原生文字和按钮不缩小。人物与生物使用四帧步行图集，平滑跟随本机模拟位置，按距离播放迈步、摆臂或爬行；移动中保持不透明，不再淡出换位。单位位于房屋或建筑后方并被实物遮挡时显示当前步态的半透明空心轮廓，离开遮挡恢复实体。房屋、门、围栏、每座建筑和每件防御设施独立管理，正门按完好／受损／破开切换专用图形，修补后回切。绘制目标60FPS，暂停同时冻结位置与步态。实际赶路时间、作业、攻击和资源结算由本机固定步长模拟决定。持续掉帧时自动降低画布像素负担，暂停和闲置时停止重绘。

## 启动

需要 Node.js 22.13 或更新版本；当前验证环境为22.20.0。首次取得代码时运行：

```sh
npm ci
npm run build
npm start
```

打开 [本机游戏](http://localhost:4173/)。存档保存在当前网址下的浏览器 IndexedDB；`data/game.sqlite` 仅保留旧版数据与迁入来源。页面需通过 HTTP(S) 服务打开，不能双击 HTML 文件。

手机与电脑连接同一 Wi-Fi：

```sh
HOST=0.0.0.0 npm start
```

选择终端打印的 Wi-Fi 网卡地址，例如 `http://192.168.x.x:4173/`。服务端口可用 `PORT=4180` 修改，数据库可用 `DB_PATH=/绝对路径/game.sqlite` 指定。

开发时在两个终端分别运行：

```sh
npm run dev:server
```

```sh
npm run dev
```

Vite 将 HTTP API 代理至4173端口；正式构建由 Node 同源提供。修改前端后运行 `npm run build` 更新正式试玩，修改后端需重启 Node。

## 保存规则

**白天按操作保存 → 入夜前保存准备 → 夜战只在内存运行 → 结束后一次保存整夜结果。**

正式存档位于浏览器 IndexedDB 的 `dawn-browser-saves` 数据库。白天操作、入夜准备、清晨检查点、夜战结算和重开都在本地完成，无需联网；保存成功后显示“进度已保存到本机浏览器”。事务提交完成后才更新界面，同一事务包含状态、修订号与请求／夜战编号，防止重复扣粮、发奖或覆盖其他标签页的新进度。

夜间的移动、修补、添火、受伤和最终结算在浏览器后台线程计算，不建立 WebSocket，不发送心跳或实时指令。中途战局仍不持久化：刷新、关闭或浏览器回收页面会回到入夜前准备，同一准备沿用同一种子。切后台则暂停，返回后手动继续。

本地存储被禁用、空间不足或事务失败时保留本页尚未保存的结果，显示错误并允许重试；不会显示保存成功。夜战存储故障会自动退避重试，也可手动重试。修订冲突停止自动保存，允许保留结果重试或明确放弃后读取最新存档。

当天清晨检查点独立保存，夜战结束后可免费重试整天，恢复当天成员、库存、建设、岗位与事件；修订号继续递增。黄昏返回白天时会撤回暂结算生产，允许改岗，不重复领取产出。

同一浏览器、同一网址（含协议和端口）的标签页共用存档。Web Locks 阻止另一页在守夜期间开战或修改进度；IndexedDB 事务与修订号在没有 Web Locks 时仍防止并发覆盖。开始守夜前会重新核对准备是否已被其他页面修改。测试模式只使用页面内存，不读写正式存档。

清除 Cookie 不影响已经迁入的本地存档；清除网站数据会删除存档。更换浏览器、设备、域名或端口不会自动带走进度，无痕模式关闭后通常不保留数据。当前没有账号或跨设备同步。页面与素材仍需首次加载，本次不增加离线网页缓存。

## 旧版数据

当前浏览器首次打开且没有本地存档时，只请求一次 `/api/campaign/export`：用原有 Cookie 读取旧服务器进度与当天清晨检查点，原子迁入浏览器；迁入后不再依赖 Cookie 或服务器存档接口，也不会覆盖已有本地进度。没有旧身份时直接建立本地新档，服务器不为新玩家创建身份。

迁入失败会提示重试，避免悄悄用新档替换旧进度；也可明确选择“创建本地新档”。迁入前需重启 Node 服务以加载新接口，并在原浏览器、原网址打开。服务器原 SQLite 数据保留，旧版首日 `/legacy.html` 和原 API 继续兼容；旧版首日记录会先转换为 campaign 再导出。

SQLite 默认位于 `data/game.sqlite`，本机备份位于 `.local/backups/`。复制运行中的数据库应使用 SQLite 一致性备份；普通文件复制时先停止服务，并包含必要 WAL 文件。SQLite 与本机备份不纳入源码。

## 跨网络试玩

项目通过 Cloudflare Quick Tunnel 将本机4173端口提供给外网手机。2026-10-22已恢复退出的隧道，最近入口记录在 `.local/public-url.txt`，恢复时首页与健康接口已验证；游戏服务同步配置该地址的 PUBLIC_ORIGIN，沿用原SQLite数据库。临时隧道重建会分配新域名，新旧域名的浏览器存档独立；旧域名下的 IndexedDB 数据不会自动迁移。公网服务仍依赖这台电脑和隧道进程运行。扩大画面收尾检查时，现有隧道出现边缘TLS握手EOF，暂不能确认外网可用；本机4173的新版本已核实正常，未重建域名。

隧道正常运行时，使用同一手机浏览器和同一公网网址，从家里 Wi-Fi 换到公司网络仍可读取本地进度；更换临时域名不会自动迁移浏览器存档。

游戏进程通过 `PUBLIC_ORIGIN=https://隧道域名` 指定公网来源；只信任本机回环代理及匹配的 HTTPS 来源，HTTP 写入接口校验来源，夜战不再连接WebSocket。公网签发 Secure Cookie。

临时隧道和 Node 都需要保持运行；`caffeinate -i` 可避免闲置自动休眠，合盖、关机仍会中断服务。[Cloudflare 官方说明](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)指出临时地址可能在重建时改变。正式部署基线为 Linux + Caddy + 常驻 Node + 持久磁盘，尚未购买或部署独立服务器。

## 中央篝火（2026-10-22）

白天中央篝火保持熄灭；无需提前储备柴料，夜间添火直接扣1建材并拨旺或点燃篝火，余柴跨天保留。入夜点火开启且柴堆为空时自动转存1建材。有余柴时重燃免费，仅实际燃烧消耗柴料（1建材约167秒）；喷污只降低火势，不扣柴。夜间可添火、免费重燃、灭火和清理湿污。灭火保留余柴并停止自动照料；自动添火使用独立建材预算，不消耗燃料。
